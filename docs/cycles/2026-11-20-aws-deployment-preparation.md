## Security boundaries and remaining facts

- Cognito customer and operator clients are separate. The V3-only trigger treats the operator group as a separate identity class; operator claim authorization is checked again in the API.
- Customer client cannot write tenant/customer attributes; only trusted admin provisioning may assign them.
- Agent M2M secret is generated by Cognito and not output from CloudFormation. AgentCore example references a Secrets Manager ARN/key but contains no secret.
- Customer, operator, actor, and delegated OBO tokens in local tests are synthetic and RSA-signed with temporary test keys. They do not prove the real Cognito or AgentCore exchange behavior.
- User Pool tier/account token exchange enablement, SES sender verification/deliverability, callback URLs, and hosted domain are required real production inputs and remain unknown.
- No real production refund or payment provider is connected. The refund execution path modifies the Shadow Hunter demo ledger.

Release verdict: NOT DEPLOYED / NOT LIVE-VERIFIED. Local code and IaC can be implemented without an AWS account; live production behavior cannot be proven without the actual managed services.
