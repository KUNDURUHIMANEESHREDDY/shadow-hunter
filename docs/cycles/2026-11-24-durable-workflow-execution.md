# Step 7: explicit durable workflow execution

Implemented account-scoped SQLite graph checkpoints, normalized node IDs, atomic single-node claims, verified result storage, explicit advancement and deletion. Before dependent execution, the verifier rechecks all ancestors and current capability permissions without re-invoking their completed adapters. An expired claim marks the uncertain node interrupted; it is never automatically replayed. Descendants are blocked, independent pending nodes can still advance.

Scope and privacy: saving is explicit, exact utility inputs and verified public-data outputs are retained, private order/support capabilities are excluded. Seven-day retention (lazy cleanup), 12 workflows per owner, 500 globally. The lease lasts 120 seconds. Historical results are not live evidence. No automatic restart worker, parallel persistent execution, or replay of uncertain nodes. Existing synchronous graph executor remains unchanged.

Validation: 10 new durable-workflow tests and 52 existing verification/recovery/scheduler tests passed. Three browser tests passed. A separate two-process smoke test completed a numeric node in one Python process, reopened the same temporary database in a different process, and executed only the remaining conversion; the first checkpoint was preserved and its adapter was not invoked again. This proves restart between checkpoints, not recovery of arbitrary in-flight side effects. Expired-claim recovery was tested with a controlled clock. Full regression, deployment and publication remain separate release steps.
